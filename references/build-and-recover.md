# 制作工具与故障恢复

## 直接制作，避免跨簿复制旧透视图

`scripts/build_case.py`需要Python和`lxml`（优先使用工作区依赖中的运行时）。它将**原始Excel包**作为输出基础，原始案例数据、说明、未选模板部件保留，追加新分析页、真实透视表/缓存、原生图表，填写需求分析并在选定原模板排版。参考只提供样式，缓存与数字由当前输入重建。支持变化后的数值和分类，不要求数据与参考相同。

先根据数据生成临时`plan.json`，再在技能目录运行：

```bash
python scripts/build_case.py "/path/to/原始.xlsx" --plan "/tmp/plan.json" --output "/path/to/完成版.xlsx" --report "/path/to/图表分析.txt" --manifest "/tmp/制作数据.json"
```

输出路径必须是新文件；不会覆盖输入或已有交付。`--dashboard`默认模板设计3，可选择原始文件已有模板；`--reference`可改用本次指定成品。不把临时失败的“制作中”副本当成新的原始输入。

计划结构：

```json
{
  "title": "根据实际期间和案例自拟看板标题",
  "analyses": [
    {
      "layer": "中层销售分析",
      "title": "各产品销售额对比",
      "row": "产品",
      "value": "订单金额",
      "filter": "所属市场",
      "chart": "column",
      "sort": "descending"
    }
  ]
}
```

上面只示范单项结构，实际至少6项、6种有意义形式，至少一项有有用的`filter`。按整体→中层→基层排列，相同`layer`相邻。`row`/`value`必填，`column`用于多系列结构，`filter`用于有效动态切换；字段名与当前输入表头一致，彼此不重复。水平长度统一；可选`height_rows`（8–40）指定垂直高度所占的默认行数，实际同排取两图所需高度的较大值，上下沿对齐，不同排可不同高。默认按图形与标签需求确定高度。整排保持相同左右边距。`sort`为`category`（按类别/时间顺序）或`descending`（按合计降序）。

支持的`chart`：`line`折线、`pie`普通饼、`column`柱形、`bar`条形、`stacked-column`堆积柱形、`stacked-bar`堆积条形、`percent-column`百分比堆积柱形、`percent-bar`百分比堆积条形、`percent-area`百分比堆积面积。普通饼限单维且≤6类别；六项中存在多个很小扇区时，工具会按当前值自动选用原生复合饼，拆分项只引用原始类别，不新增“其他”数据。工具能力不构成对用户选题的限制；确有需要的其他形式可扩展或使用原生工具实现，不能默默改题凑类型。

每项可带`analysis`，顶层可带`summary`，用于写入经核实的中文分析。省略时工具只生成可核对的事实草稿，**必须按manifest重新完善趋势、结构、基层含义及总分析**，不能把模板式最高项说明原样当成最终报告。用实际期间命名；多年度不能仅按“下单月”混合，应先选择合适日期分组或扩展处理。

## 原生应用完成最后几步

1. Excel正常打开生成文件，确认没有恢复/修复提示。点击一个分析页透视表，应能显示真实字段面板与正确行/列/筛选/求和项。检查饼图分母和系列缓存，只含真实类别，不含总计、汇总标题或复合饼的“其他”重复值。
2. 由`filter`项选择动态图。某些Excel版本不显示透视图字段按钮，不能因此断言不能做动态图。此时在对应分析页点击透视表，使用“数据透视表分析→插入切片器”，选择计划的筛选字段。**同工作簿内**剪切切片器并粘贴到看板，保留原透视表连接。
3. 用切片器“报表连接”确认仅连接所需透视表，避免筛选影响本来应展示全体的图。保留清除筛选入口，选用匹配模板的样式并放在不遮挡图例、标题、绘图区的位置。横向按钮应真实调整整个切片器及按钮尺寸，再核对界面，不能只改了属性框就认为排版完成。
4. 在看板依次选择“全部”、两个不同类别，核对分析页与看板两图同时变化，值与当前源记录汇总一致；恢复默认状态。保存并重新打开，再检查饼图比例、缓存和控件。
5. 全部分析与完整看板视觉检查，清除全表选中/分组工作表等编辑状态。字号、配色、文本框按参考；水平长度统一，垂直高度按图形调整，同排取一致高度并上下对齐，不同排可不同高，各排整体左右外沿对齐，边框四边完整位于模板内边距中。分析页图表区纯白填充，看板无填充；饼图不显示图例，名称与百分比在扇区内且清晰。按实际内容优化行高列宽与留白。最后完善TXT，仅交付Excel与TXT。

## 本类问题的恢复顺序

| 发现的问题 | 继续完成的方法 |
|---|---|
| 跨簿复制透视图后占比或系列变了 | 保存失败副本作诊断，从未操作原件重新制作；用当前透视结果重建系列/缓存，不继续复制同一旧图。单维占比且标签清晰可读时用普通饼；小扇区挤压时从原始类别重建复合饼，不强行复用旧子母饼 |
| 百分比变化但原因不明 | 比对源汇总、透视表、实际系列缓存及分母；不能只看一个标签就断定是Excel重复计算 |
| XML能解析，但Excel报损坏 | 按部件隔离样式/图表/透视缓存定位；检查Office数据类型标记及元素顺序。文本/空值等缓存的`containsSemiMixedTypes`必须正确，见[Microsoft说明](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/e6bf5edd-aa4c-40b5-8f43-b3da6b664823)。本工具已处理这些已验证的兼容要求 |
| UI操作或读取超时 | 重新获取当前状态，只重试尚未完成的步骤；已经保存的构建成果继续使用。不要一条超时便终止全部制作，也不要覆盖输入来“重试” |
| 某图类型不适合当前数据 | 保持所要回答的问题，选择贴切形式并重新检查6类6图，不为了复制图样更改统计口径 |
| 静态检查通过，交互未测 | 继续执行上面的原生验证，不将待办写成最终答复而把工作留给用户 |

如果必须结束，明确说明是哪项已证实的外部条件不能继续，保存可恢复的中间状态并列明未完成内容。普通的可修复错误或“需要进一步验证”本身不是结束条件。

## 修复已有输出的排版

```bash
python scripts/polish_case.py "/path/to/已生成.xlsx" --output "/path/to/排版修正版.xlsx"
```

只在新的副本中调整所选模板的行高/列宽、图框锚点及分析页对应尺寸，并将拥挤的小扇区改为原生复合饼；不重建源数据、透视表、透视缓存或筛选连接。更新需求分析中的实际图形名称。依旧保留两处背景差异。

本模板默认使用明确14pt行高和较宽列网格，图框约528像素长，约261–317像素高，同排高度一致。普通行间留约两行、板块间留出小标题空间。这是可按内容调整的起点，最终以整体比例、完整边框、标签不挤和保存重开后无相交为准；不要把“同排对齐”当成美观验收已经通过。

复合饼实现参考：[Microsoft OfPieChart](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.ofpiechart?view=openxml-3.0.1)。使用自定义拆分索引与原始六项缓存，不能复制带旧标签/拆分状态的参考对象后仅换标题。

## 按当前模板修复颜色

```bash
python scripts/chart_theme.py "/path/to/已有看板.xlsx" --output "/path/to/配色优化版.xlsx" --dashboard "模版设计1"
```

按文件中的真实工作表名传入`--dashboard`；只有一个模板时可省略。工具仅修改选中模板图表、文本框及各分析页对应图的颜色，并修正新文件的自引用前缀；不改数据、缓存、透视表、锚点或布局。`build_case.py`和`polish_case.py`也自动调用同一配色逻辑。原始模板及未选模板不改色。

颜色按实际背景解析而非模板编号硬编码。内部以普通文字对比度≥4.5、数据填充≥3、细折线≥4.5作为检查起点；网格线用较弱中性色，最终仍须用Excel实际查看。白底分析页与深色看板分别配色；饼图逐扇区设置可读的名称和百分比，保留无图例，不引入金额、系列名或小图例符号。字体字号保持参考，先调整颜色，不能以加粗或缩小字掩盖低对比问题。
